# Unit 1 environment checklist

Capture evidence from the team machine or machines used for the course. Replace bracketed fields in the captions with observed values. Crop account identifiers, credentials, and unrelated files before submitting screenshots.

| Instructor category | Details | What to capture | Caption template |
| --- | --- | --- | --- |
| 1. Environment Configuration | To be recorded by the team. | System information showing CPU and installed RAM, plus storage settings showing capacity and free space on the workspace drive. | Team development machine has [CPU], [RAM], and [available space] free of [total capacity] on the workspace drive. |
| 2. Operating Environment | To be recorded by the team. | OS edition/version and the HoneyDoo workspace open in the IDE or file manager. | [OS edition and version] with the HoneyDoo workspace open at [project folder]. |
| 3. Development Tools | To be recorded by the team. | IDE About dialog or version screen, `dotnet --list-sdks`, and `git --version`. Record the version the team actually uses. | [IDE and version], .NET SDK [version], and Git [version] are installed for HoneyDoo development. |
| 4. Platform Readiness | To be recorded by the team. | Initial solution in Solution Explorer, team repository if configured, or completed local configuration. | HoneyDoo platform preparation shows [solution, repository, or configuration] on [date]. |

Unit 1 does not require a running application, populated database, virtual machine, or shared hosting. If the team captures a running starter page, label it **Application preview**. Capture hardware and tool information separately using the evidence above.
